# Take Break

Приложение для регулярных перерывов. Текущий стек — **React Native + TypeScript**. Дизайн берётся из исходного WPF-интерфейса: `Assets/main.png` и `Assets/blur.png`.

## Статус переноса

- Общие React Native-компоненты настроек, HSV-палитры, экрана перерыва и мини-панели находятся в `src/ui`.
- Расписание, настройки, таймер, удержание кнопки и обработка снимков перенесены в TypeScript: `src/core`.
- Для **Linux** реализована оболочка **React Native Web + Electron**: окна, трей, автозапуск, захват экрана и файловое хранение настроек.
- Для **Windows/macOS** добавлены зависимости React Native Windows/macOS, JS-точка входа и интерфейс нативного адаптера. **Нативные host-проекты и модуль `TakeBreakPlatform` пока не реализованы. Полноценные нативные приложения для этих ОС ещё не готовы.**
- Старая реализация и сборка на Go удалены. Сборки Windows/macOS нельзя считать готовыми только потому, что общий TypeScript-код проходит проверки.

## Установка и проверки

Нужен Node.js 22+; в CI используется Node.js 24.

```sh
npm ci
npm run typecheck
npm test
npm run build
```

`npm run build` создаёт **web-бандл и Electron JS-бандлы**, а не нативный Windows/macOS EXE или `.app`.

`node_modules/`, результаты сборки, установщики и кэши исключены из Git. В репозиторий должны попадать `package.json` и `package-lock.json`; зависимости после клонирования устанавливаются через `npm ci`.

## Предпросмотр интерфейса

```sh
npm run web
```

Откройте `http://127.0.0.1:5173`. Это браузерный предпросмотр React Native Web, не полноценное desktop-приложение: он не имеет доступа к системному трею, файлам, автозапуску и рабочему столу.

## Linux / Electron

```sh
npm run linux
npm run smoke:electron
npm run package:linux
```

Для запуска нужна графическая сессия и системные библиотеки Electron. Установщики создаются в `release/`. На Wayland захват экрана и положение окон ограничиваются композитором; разрешение на захват может запрашиваться через системный portal. Если захват запрещён, используется тёмный фон.

`smoke:electron` открывает настоящие окна и проверяет настройки, палитру, отмену, запуск перерыва, мини-панель и восстановление. Результат записывается в `TakeBreak-rn-smoke-result.txt` в системной временной папке. Проверка использует отдельные временные настройки и не меняет автозапуск пользователя.

## Windows/macOS

Запланированы нативные React Native Windows и React Native macOS, не Electron. Для завершения интеграции необходимы host-проекты и реализация контракта `src/native/client.ts`:

- хранилище настроек и автозапуск;
- создание и закрытие окон для всех сцен;
- захват мониторов;
- системный трей / menu bar;
- события блокировки, сна, изменения мониторов и фоновые тики таймера.

Команды `npm run windows` и `npm run macos` требуют этих проектов и соответствующих SDK: Visual Studio с C++/Windows SDK или Xcode/CocoaPods. Сейчас они не являются подтверждённым способом запуска готового приложения.

## CI

В `.gitlab-ci.yml` и `.github/workflows/build.yml` настроены проверки TypeScript, модульные тесты и сборка общих web/Electron-бандлов. Эти проверки **не собирают и не проверяют нативные Windows/macOS host-приложения**.

## Файлы в GitLab Release

### Автоматически: Linux x64

После коммита конфигурации и отправки тега вида `v0.8.0` GitLab CI проверяет код, собирает Linux x64 (`AppImage` и `tar.gz`) и публикует файлы в **Deploy → Releases → нужный тег → Assets / Links**. Например:

```sh
git tag v0.8.0
git push origin v0.8.0
```

Тег должен указывать на коммит с актуальной `.gitlab-ci.yml`. Нужен Linux runner с Docker executor и доступом к npm, загрузкам Electron и GitLab API. Нативные Windows/macOS-файлы этот pipeline пока **не собирает**.

Файлы загружаются в **GitLab Generic Package Registry**, затем ссылки добавляются в Release. Они не зависят от истечения срока CI-артефактов. Registry должен быть включён в настройках проекта; не удаляйте опубликованные версии пакета `take-break` политикой очистки. Для приватного проекта скачивание требует доступа к проекту.

CI использует `CI_JOB_TOKEN`. Если политика GitLab запрещает нужные API для job token, настройте masked-переменную `GITLAB_TOKEN` с правом `api` и доступом к проекту; для protected-переменной тег также должен быть protected. Реальная сборка Linux и публикация проверяются на runner: локальные проверки скрипта используют тестовый HTTP-сервер, не GitLab.

### Вручную: добавить готовые файлы любой платформы

Положите установщики/архивы **непосредственно в `release/`**. Например: `TakeBreak-0.8.0-windows-x64.exe`, `TakeBreak-0.8.0-macos-arm64.dmg`, `TakeBreak-0.8.0-linux-x64.AppImage`. Нужны уже собранные файлы; скрипт публикации не создаёт приложения из JS-бандлов.

Проверьте список без загрузки и без токена:

```sh
npm run release:gitlab -- --tag v0.8.0 --project group/project --dry-run
```

Затем задайте переменную окружения `GITLAB_TOKEN` с правом `api` и выполните ту же команду **без `--dry-run`**:

```sh
npm run release:gitlab -- --tag v0.8.0 --project group/project
```

Для собственного GitLab добавьте `--url https://gitlab.example.com`. Вместо `group/project` можно указать числовой ID проекта. Тег должен уже существовать в GitLab. Токен не добавляйте в файлы проекта, URL или аргументы команды.

Скрипт создаёт Release либо дополняет существующий, сохраняя прежние ссылки и описание. Поддерживает `.exe`, `.msi`, `.msix`, `.msixbundle`, `.zip`, `.dmg`, `.pkg`, `.AppImage`, `.deb`, `.rpm`, `.tar.gz`, `.tar.xz`; вложенные папки и JS-бандлы не загружаются. Повторная загрузка одинаковых файлов безопасна; другое содержимое с тем же именем и тегом отклоняется. Для новой сборки используйте новую версию или имя файла.

`release/` остаётся в `.gitignore`: установщики публикуются через API, а не коммитятся в Git. Для другого каталога используйте `--dir путь`, для текста релиза — `--notes-file CHANGELOG.md`.

## Структура

- `src/core` — общая логика на TypeScript, совместимый с предыдущей версией формат `settings.json`.
- `src/ui` — общие React Native-компоненты с исходным оформлением.
- `src/native` и `src/NativeApp.tsx` — точка подключения нативных host-приложений.
- `electron` — системная интеграция Linux и безопасный IPC через preload.
- `web` — вход для React Native Web и браузерного предпросмотра.
- `tests` — проверки расписания, настроек, HSV и состояния таймера.
- `scripts/build-electron.mjs` — сборка Electron JS-бандлов.
